# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

pnpm 12 + Turborepo monorepo. Node `^22.22.3 || ^24.15.0 || >=26` (set by the Nest CLI 12 toolchain). `engineStrict: true` in `pnpm-workspace.yaml` makes install fail on an older Node. pnpm 12 ignores `engine-strict` in `.npmrc`.

```bash
pnpm install
pnpm dev                                   # turbo watch dev: web on :3000, api on :3001
pnpm build | pnpm lint | pnpm typecheck    # all workspaces
pnpm turbo run lint --filter=@aure/web     # one workspace
pnpm --filter @aure/web exec eslint src/routes/index.tsx   # one file
pnpm --filter @aure/web start              # run built web server (.output/server/index.mjs)
pnpm --filter @aure/api start              # run built api (dist/main.js)
pnpm stack:up -- --fresh | pnpm stack:down # whole built app: throwaway Postgres :55432, api :3457, web :3100
PLAYWRIGHT_CHANNEL=chrome pnpm test:e2e    # Playwright (apps/e2e): builds, starts the stack, runs api + web projects
pnpm --filter @aure/e2e exec playwright test tests/api/health.spec.ts   # one spec (reuses a running stack)
```

Tests are Playwright end-to-end only, in `apps/e2e`, run against the stack from `scripts/stack.mjs`. There are no unit tests. `@aure/e2e#test` depends on the api and web builds and is never cached. Build before typecheck when routes change: `typecheck` doesn't wait for the web build, which regenerates `routeTree.gen.ts`.

Every turbo task depends on `^build`, so workspace packages build before their consumers.

## Agents

Project subagents live in `.claude/agents`. Each preloads its skills from `.claude/skills`.
- **backend-developer** owns `apps/api`, plus the contracts and db changes an API change needs.
- **frontend-developer** owns `apps/web` and `packages/api-client`.
- **code-reviewer** reviews changes against the project standards (`.claude/skills/aure-code-standards`), and never edits.
- **qa-verifier** independently verifies features or the whole app, and never edits.
- **test-engineer** owns `apps/e2e`.

Typical flow: developer builds and self-checks → code-reviewer reviews the diff → qa-verifier accepts or rejects with evidence → findings and bugs go back to the owning developer → test-engineer turns verified flows into regression tests.

Naming, file structure and stack rules are written down in `.claude/skills/aure-code-standards` (overview plus `references/*.md` per area). Run `node .claude/skills/aure-code-standards/scripts/check-standards.mjs` for the mechanical checks.

## Layout

- `apps/web`: TanStack Start (React 19, Vite 8, Nitro node-server output). File-based routes live in `src/routes/`. `src/routeTree.gen.ts` is generated by the Vite plugin on dev/build. Commit it, never hand-edit it, and ESLint ignores it.
- `apps/api`: NestJS 12, CommonJS, global prefix `/api` (health check at `GET /api/health`).
- `packages/config-ts`: shared tsconfigs (`base`, `library`, `react-library`, `nest`, `start`).
- `packages/config-eslint`: shared flat configs (`base`, `nest`, `start`, `react-library`).
- `apps/e2e`: Playwright suite, with projects `api` (request fixture) and `web` (browser; tests fail on console errors).
- `scripts/stack.mjs`: starts and stops the whole built app for verification and e2e runs. State and logs live in `.stack/` (gitignored).
- `packages/{contracts,db,api-client,config-env}`: placeholders with an empty `src/` and no `package.json` yet. The scaffold scripts in `.claude/skills/*-feature-*` create them on first use. Their intended roles are encoded in the lint rules below.

## Architecture rules (enforced by ESLint, not convention)

- **Web never touches the database.** `apps/web` may not import `@aure/db` or `pg`. It must go through `@aure/api-client` to the API, so authorization and validation live in one place.
- **API layering is DB -> mapper -> contract.** In `apps/api`, only `*.repository.ts`, `*.mapper.ts` and `db.module.ts` may import `@aure/db`/`pg`. Controllers and services work with `@aure/contracts` types (zod is in the catalog for this).

## Non-obvious constraints

- **Nest + type imports:** `apps/api` keeps `verbatimModuleSyntax: false` and `@typescript-eslint/consistent-type-imports` off.
  - Classes Nest injects by type need plain imports. `import type` erases them, so `emitDecoratorMetadata` emits `Object`, and DI fails at runtime with no compile error.
  - Non-class types in decorated signatures (zod-inferred contract types in `@Body()`, token-injected `Pool`) need `type` imports, or TypeScript fails with TS1272 under `isolatedModules`.
- **Versions come from the catalog.** Put shared versions in `pnpm-workspace.yaml` `catalog:` and reference them as `"catalog:"`. Overrides and `allowBuilds` also live there, because pnpm 12 ignores the `pnpm` field in `package.json`.
- **Packages newer than 24h can't be installed** (`minimumReleaseAge: 1440`). When pinning, pick the newest release older than a day.
- **TypeScript is pinned to 6.0.x** via override: `@nestjs/cli` and `typescript-eslint` don't support 6.1+/7.
- **Native builds are opt-in.** A new dependency with a postinstall/native binary must be added to `allowBuilds`, or it silently never builds.
- **`base.json` is strict** (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`), and linting uses `recommendedTypeChecked`.
